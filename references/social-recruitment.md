# 官网社招推荐与执行

读取案例 `search-preferences.json`，没有时从用户沟通与事实库提取，未知条件标为待确认。字段可包含地点、薪资底线、感兴趣公司、排除公司、岗位方向、来源日期。排除公司覆盖既往雇主及可核实的同名/品牌别名；不要把这些个人条件写死在共享 Skill。

用户要求“大厂”是公司偏好，不代表有高级岗位资历。分别列公司兴趣、可迁移证据、岗位硬门槛与未知项。经验年限须按实际相关经历及全职/兼职性质计算，不能简单把重叠时间相加，也不能把个人产品等同商业产品负责人经历。

在公司官网进入**社会招聘**；不把校招、实习或第三方聚合页当成合格社招。搜索词取自证据支持的方向，如用户运营、知识库、AI 内容质量、交付支持、初级产品运营。每个候选岗位记录公司、职位编号、完整 JD、城市、雇佣类型、网址、读取时间、薪资是否公开、硬门槛、匹配证据与下一动作。官网页面失效或无法读取时保留线索，不能进入待提交队列。

把结果写入 `company-shortlist.md`，清楚区分“推荐公司”“岗位线索”“已核验待准备”“就绪待提交”。公司名单不是有效职位列表；薪资未公开也不能推断达到用户底线。

每个已核验岗位走既有 `resume_pipeline` 与 `job_data`：独立材料、validate/register、必要事实核对、start 冻结、授权范围内浏览器填写/上传/提交、record 核验真实回执。用户已授权范围内不反复确认，但不可用未核实信息填写必填事实。验证码、本人签署及工具要求接手的动作停在对应步骤。恢复时先查 started/unknown，避免重复投递。

没有实际后台执行器或调度任务时，不能声称关掉对话后仍会自动投递。UI 的“复制官网社招执行指令”只是给 Codex 的任务入口，不是已接入通用 ATS 自动投递服务。
