# 网申、邮件和外部记录

## 执行条件

开始前核对目标岗位、材料清单、用户授权和已有投递历史。准备材料不自动授权外发；用户明确要求投递某个岗位时，按该授权完成，不额外设置例行确认。范围不明则先完成可审阅材料再问缺失范围。

按 [数据约定](data-contract.md) 记录本次 attempt_id、冻结附件和执行前事件，再产生外部动作；恢复时先核验未完成尝试。网页保存草稿或上传即可能传输资料，遵守用户“仅本地准备”等限制。

优先使用可用的专用连接器/API；其次使用已登录浏览器的可用自动化能力。不要假定存在 Playwright、Simplify、Outlook 或 Gmail。技能说明本身不提供这些服务的连接。登录和验证码交由用户，不绕过。

## 网申

1. 核对公司、官网域名、职位编号和地点，打开真实岗位。
2. 逐页读取字段，匹配证据库和已确认答案。填写后读取页面核验，不仅依赖动作成功返回值。
3. 必填但未知的工作许可、薪资、推荐人、离职原因等向用户提问，并继续其他独立字段；确认答案按适用范围保存。不能为了过表单填随机值。
4. 上传授权范围内的岗位附件。核对自动解析出的工作日期、雇佣性质和教育信息，纠正 ATS 解析错误。
5. 提交前检查必填错误、文件版本和声明。订阅营销、人才库长期保留等可选授权不自动勾选；遇到本人签署或新的承诺，交由用户处理相关项。
6. 已有明确提交授权则执行；否则停在可审阅页面，给出材料和缺失授权。成功后保存确认页/编号或可核验回执再更新记录。

## 邮件

用户授权发送时核对收件人、主题、正文、附件以及是否已有同一岗位邮件。发送后确认工具语义是已发送，而非仅创建草稿或排队受理；必要时检查已发送记录。仅有消息标识不必然表示已发送。若发送超时或仍在队列，保留待核实状态，不重复发同一封。区分正式申请、咨询与跟进，按数据约定记录阶段。

## 恢复与停止

批量任务按已核验短名单逐个执行，每个岗位仍需独立匹配、材料与回执。记录计划数量、已准备、已提交、失败及待核实数量，不能用同一模板群发来凑数。用户授权批量提交后，在范围内继续，不逐条重复请求授权；新增必填事实或超出范围的动作再处理缺口。用户仅引用“申请 500 个”的视频话术不构成实际投递指令。长任务保存可恢复队列，不声称对话结束后会继续运行，除非实际配置了用户授权的后台执行能力。

保存 `checkpoint.md`：页面/步骤、已完成字段、未完成字段、所用附件、阻塞原因和下一动作，不写会话凭据。相同操作连续两次失败且没有新诊断信息时停止重试并给出接手步骤；提交结果未知时立即设置 execution_status=submission_unknown 核查，不再点击。

平台出现风控、验证码或访问限制时停止自动操作该入口。可以准备官网材料或手动填写清单，但不能声称所有平台都存在某种固定风控。

## 飞书同步

本地记录为默认事实源。用户要求同步且有可用连接器时，确认目标表/字段，使用 job-key 查重并更新。只传递必要进度字段，不上传整个证据库。目标不明时先生成本地待同步内容再询问。

没有连接器则交付 CSV，并标记“未同步”。同步失败不能回滚已完成的真实投递状态；分别记录 status 与 sync_status，旧字段按数据约定兼容。对外同步授权不能扩展成发消息给 HR。
