# 批量选岗、共同缺口与跟进

当用户给出多份 JD、询问先投哪份/先补什么，或要求查看需要跟进的申请时加载。复用当前案例事实源、偏好与投递事件，不新建第二份主档。

## 页面与本地脚本

启动现有 `scripts/resume_server.py --case <案例绝对路径>`，从「投递进度 → 批量选岗与跟进」进入 `/strategy`。

批量导入 JSON 数组（页面也接受下方对象）。正文必须为已获取的实际 JD；仅有 URL 的条目标为缺正文，不根据标题推测。

```json
{"jobs":[{"company":"合成公司","title":"知识库运营","jd":"任职要求：知识库整理；SQL 查询能力","url":"https://example.test/jobs/123","deadline":"2026-12-01"}]}
```

可选 `posted_date` 使用 `YYYY-MM-DD`；一次最多 100 条，请按页面请求大小拆分长 JD。CLI：

```bash
python3 scripts/search_strategy.py --case /absolute/case --jobs /absolute/jobs.json
python3 scripts/search_strategy.py --case /absolute/case --days 10
```

前者保存不可覆盖的 `generated/strategy-*/request.json` 和 `strategy.json`，后者只读台账及事件并输出草稿。页面默认静默阈值 10 天，CLI 可调整。报告记录生成日期；截止状态随本次分析计算，需重新分析才会刷新。没有后台定时监控。

## 排序与解释

- 使用现有 `load_evidence()` 校验事实源摘要，并沿用 `jd_requirements.assess()`。这是有限规则的初筛，不是完整语义评估；即使 100 分也必须人工核对 JD、地点、语言和资格。
- 初筛分为已支持要求权重 / 全部识别要求权重 × 100，必需项权重 3，其余 1。明确不满足必需项列为 blocked，未知必需项列为 needs_review；均排在可继续审阅岗位之后，不生成 ready 状态。
- URL 去掉已知追踪参数后去重，保留职位编号参数及 `#` 后的路由片段，避免合并单页招聘网站中的不同岗位。台账已有相同规范化链接则标记 tracked；公司排除名单来自 `search-preferences.json`。不同 URL 是否同岗仍需核验，不以同名自动合并。
- 只对明确的 ISO 日期判断截止，7 天内提示紧急，同分优先。日期不合法保留待核实；发布超过 30 天只提示核验，不等同过期。没有联网验证，不从无法访问推断岗位关闭。

## 共同缺口

按技能名或相同原句聚合未支持要求，显示原岗位序号、原句与状态。仅合并少量明确技能名，其余同义要求可能分开，需在对话中进一步归并。优先级是涉及岗位数 + 必需项岗位数 × 2；排除、过期、已跟踪和重复条目不进入本批统计。

unknown 先查证据，不直接判为不会。学历、年限、许可、地点与意愿首先核实，不能写成「七天补齐」。可训练技能再制订练习作品、可复现步骤、自评标准与合理时间估计；需要课程资源时另行核验公开来源。本地脚本只给下一动作与交付物，不声称已检索课程。练习不能自动进入职业事实库。

## 跟进规则

从 `application-tracker.csv` 取 submitted/assessment/interview，必须有 `attempt_result/submitted` 事件。静默时间以最后一次已记录的投递、回复、测评、面试或成功跟进的观察时间计算，不猜测历史发生日期。未知执行状态、未决申请尝试、未来时间或冲突阶段先核实。

确认事件须关联有效的 `attempt_started`；本轮观察事件须有来源及案例内证据文件。历史记录不完整时先提示补核，不生成草稿。跟进次数从该轮申请开始统计，延迟确认成功不能重置已发送次数；相同事件 ID 不重复计数，内容冲突则报错。

每轮已确认申请最多提示两次成功跟进，`followup` 事件的 `result: sent` 才计数。`draft`、`not_sent`、`failed` 不计数，其他不明结果暂停提示。沿用 `job_data.py record` 保存真实回执；生成草稿本身不写事件，也不更改招聘阶段。

草稿只询问招聘进展，不新增能力主张，不猜收件人。真正发送前检查最新邮箱/平台回复、同岗其他渠道跟进及已有授权。记录面试后可按本次内容写感谢草稿；没有用户指令不自动发信。

## API

`POST /api/strategy/rank` 接受上述对象，复用本地会话令牌与写入锁；`GET /api/strategy/followups` 使用同一令牌。页面从已存在的 `/api/bootstrap` 建立会话。本功能仅适用于现有本地服务，不部署到公开静态预览。
