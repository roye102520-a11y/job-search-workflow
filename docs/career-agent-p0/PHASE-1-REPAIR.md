## 匹配结果规则

`matching()` 先判断官方状态、学历/毕业窗口/在校资格/经验/工作许可、雇佣地点、薪酬和屏蔽名单，再汇总有来源的工作或项目证据。结果带 A/B/C/D/U 等级、逐项原因、证据引用、检查时间、规则版本和 P0/P1/P2 目标方向；原有数字只称“证据覆盖分”，明确不是录用概率。

薪资底线仍以私人档案原文为准。原文没有结构化币种和周期；除明确无薪可判 D 外，当前薪资未知或比较口径未确认时保持 B/U，不默认为达标。私人偏好文件未被覆盖。

毕业时间可以从已校验的职业事实来源中读取明确的“毕业时间”字段，引用来源为 `career-evidence-bank.md#毕业时间`。这不代表当前在校状态；只限在校生的岗位在学籍事实缺失时仍需核实。

## 私人数据保护

`resume-evidence.json` 的 coaching 来源摘要在开发前已过期。审阅当前来源后确认差异只来自持续更新的学习记录，没有新增工作成果或项目贡献。开发前先备份原缓存，然后仅更新该来源摘要。更新后使用现有 `load_evidence()` 真实加载通过。备份留在本机求职案例目录；真实档案、备份和任何真实岗位结果均未纳入 Git。

投递 Tracker、Manifest、事件日志、简历版本和项目别名在本阶段没有写入。合成测试验证了重导入不会改写已投递阶段、JD 文件和事件；发现岗位仍记为 `discovered`，没有创建提交事件。

## UI 与安全边界

本阶段没有修改 HTML、CSS、前端 JavaScript、导航或组件。相对基线提交 `d7ea61e`，`assets/` 与 `public/` 无变化；上一轮审计所记录的视觉对照继续适用，本阶段没有伪称重新拍摄或重跑浏览器截图。

F01 条件性 LAN 风险仍待独立安全设计：仅在用户显式选择非 loopback 绑定且其他设备可访问时成立。默认仍为 `127.0.0.1`；新岗位 API 额外拒绝非 loopback 客户端。本阶段不把已有 LAN 模式误报为已修复，也不扩大真实数据的网络访问范围。

## 验证与未完成范围

完整自动化测试共 180 项：179 项正常通过，1 项保留为 expected failure，即 F01 显式 LAN 模式的旧安全风险。URL、资格、缓存、重复导入/恢复、官方 ATS 解析和 token/loopback API 均有合成回归测试。`git diff --check` 通过。

SmartRecruiters API 使用官方公开详情接口结构；本阶段只用合成响应验证解析，不做在线岗位检索。其它 ATS 解析器的在线字段变化未做实网验收。Career Studio 界面仍没有岗位发现入口；投递看板中的岗位状态、材料版本、渠道和真实回执展示属于第三阶段。真实岗位筛选属于第二阶段，均待用户确认进入下一阶段。
