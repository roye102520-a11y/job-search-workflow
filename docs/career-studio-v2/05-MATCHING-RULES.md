# 匹配与选材规则 V2

## 岗位路由

四个支持方向保持不变。正文每个明确词项计 3，标题影响上限 1；低分、没有足够正文或两个方向接近时标 ambiguous。输出主方向、次方向、正文/标题命中词、不确定项和确认入口。用户手动方向覆盖支持范围内的建议；unsupported 工程岗位和职责不清的 AE 不因手选而伪装可投。分数仅为规则排序，绝不是招聘概率。

否定按短句排除，避免一句「不要求知识库，负责用户运营」全部被删除。仍不是通用语义模型，复杂例外必须人工复核。

## 硬条件

| 状态 | 含义 | 必需项影响 |
|---|---|---|
| supported | 直接表述证明已识别要求 | 仍需人工审核 |
| partial | 部分条件/相邻实践，场景或深度未完整证明 | 阻止就绪 |
| unknown | 缺事实、缺完整性或规则无法判断 | 阻止就绪 |
| not_met | 完整且确认的事实或明确否定证明不满足 | 阻止就绪 |

教育只读取当前档案；专业与层级分别谨慎处理。工作年限按全职月份并集，不加兼职、实习或重叠岗位，不计未来月份；不足且资料不完整时不判明确不满足。英语、出差、许可不从地点、课程或相邻经验推断。标签/keywords 只能支持关联，不能单独证明 RAG、OCR 等直接能力。生产级/熟练度需要额外直接事实。

partial 已进入 summary、required_blockers、匹配 Markdown、生成结果、manifest 未决字段、岗位分析和批量界面；材料始终为 preparing。下游批量分只累计 supported，不把 partial 当完整满足。

## 选材

每条候选记录：稳定 ID、来源、已保存事实表述、简历表述、关键词命中、选择维度、最终选中状态、取舍原因和表达处理。维度包括 JD 相关性、来源强度、个人动作、可核验结果、历史准确性、重复表达惩罚、本人项目优先级和篇幅。

不再固定「每份工作两条 / 某方向一个项目 / 顶部两条」。保留安全工作时间线，再分配相关事实；不相关项目保留在候选表。最优先项目提高顺序，但不能覆盖待确认/冲突过滤。顶部亮点按独立文本预算且每段最多一条，以避免同一事实重复输出。

PDF 使用实际容量检查，保持一页与 10pt 正文，必要时减少篇幅预算；所有未选项仍可追溯。预算不是版面精确预测。若最低预算仍放不下，停止并提示复核，不裁切或缩小字体。

原始事实不改写；变更 JD、优先项目、篇幅、语言或事实摘要产生独立版本。完全相同输入与事实复用原结果，不增加投递清单。变更后的版本仍待人工审核。

## 岗位筛选

保留 shortlist/needs_verification/excluded/duplicate 字段兼容，展示为「符合已知条件/待核实/明确排除/重复记录」。薪资分月薪、明确薪数与年薪；未写薪数不默认 12，年薪未写支付次数不直接推断月薪。日薪/外币/反向区间保留未知。

双休与固定周末工作冲突明确排除；加班/值班描述待核实。实际地点有来源时优先，并显示标签冲突。屏蔽公司只做完整规范化名称和用户明确别名映射，不能推断子公司关系。相同已知 BOSS ID 去重，条件冲突不静默合并。明确来源关闭状态可以排除；缺 JD 则待核实。没有在线核验就不填 last_verified_at，不声称仍在招。
