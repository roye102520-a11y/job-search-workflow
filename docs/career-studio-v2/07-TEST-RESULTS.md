## 合成数据覆盖

career-v2-cases.json 包含 10 个普通 JD、10 个混合 JD、10 个硬门槛 JD、11 个筛选异常与 5 个事实更新/冲突场景。这里的「10方向」指 10 个不同岗位样本，模板仍明确只有 4 个支持方向，其余 unsupported/ambiguous 不伪装支持。

额外回归：不同候选人教育理由、相邻标签非直接能力、手选不能突破 unsupported、全部候选与未选原因、项目优先级、原始事实不变、旧摘要失效、同 ID 条件冲突、公司规模数值区间/部分相交/未知、复合学历不能隐藏 SQL 条件、月薪单位/12–14薪、缓存内容改变、相同请求复用、独立 JD 隔离、没有回执不计确认投递。

旧测试中关于不完整学历/年限自动 not_met 的假设已改为需要合成夹具明确完整性；关于固定两个工作要点的断言改为保留来源事实，不再强制截断。没有删除原有测试。

## 真实浏览器端到端结果

**14 / 14 项通过，0 个 JavaScript 错误。** 使用 tests/e2e.cjs 启动两个临时案例并自动关闭。实际检查：

1. 合成能力边界、五个导航入口。
2. 五种求职者路径，有明确入口/结果/下一步及焦点承接。
3. 预设岗位切换与合成人工审阅。
4. 无档案材料导入，短文本错误恢复，保留待复核原文。
5. 完整档案直接 JD 入口及保存目标。
6. 要求矩阵、全部 15 条候选、原始来源查看、右栏选材与优先级。
7. 真实 PDF/Markdown 生成、保持未投递、完全相同请求复用文件。
8. 用户手选不能使机器学习工程岗套用产品模板。
9. 六阶段看板，生成不增加确认投递数。
10. 1440 / 390px 布局没有横向溢出，跳过导航键盘入口。
11. Service Worker 白名单，没有个人预览缓存。
12. BOSS 导入、未知核验时间、改变薪资条件后重新筛选。
13. 输入键盘焦点圈实际为 3px。
14. 浏览器 JavaScript 错误数组为空。

详细结果 e2e-results.json 与 e2e-tests.log。首次启动 Playwright 时默认浏览器版本不存在，定位已安装 Chromium 后完成。增加原文查看时发生过初始化顺序错误，实际 E2E 检出，修复后重跑全部通过。不能把这些中间失败当成最后通过。
